# Campsite R5.8 — 세션 1: Web (프론트엔드 엔지니어)

문서 버전: R5.8-S1 · 2026-10-10
소유 폴더: `apps/web/**` 만 수정한다. 그 외는 읽기 전용.

## 역할과 목표

shadcn/ui 기반 컴포넌트로 **For Me 경험**을 만든다. 로그인 → 채널 생성 → Vista 도착 → 재생까지 화면을 완성한다.
업로드·사양·인프라 같은 기술 정보는 **화면 표면에 올리지 않는다.** 사용자는 콘텐츠(Vista)만 본다.

---

## 0. 공통 전제 (읽기 전용)

> 원본은 `packages/contracts`(세션 3 소유). 이 절과 다르면 contracts가 이긴다. 계약 변경은 세션 3에만 요청한다.

**이번 목표 = For Me까지.** Google 로그인 → Workspace·Plan 논리 배정 → 채널 생성(프롬프트) → Runner가 HTML 모션그래픽 Vista 생성 → 웹앱 Vista Player 재생 · For Me 피드.
**제외**: 결제, Discovery 동작, 사용자 모델 연결(G3), 채널 정기 실행(G4), Duo 접힘 레이아웃, 좋아요·댓글·포크.

**구조**: Web(`apps/web`) → Core(`services/core`: Cloudflare Worker + D1 + R2) ← outbound HTTPS만 ← Runner(`services/runner`: VPS의 Docker). Runner는 인바운드 포트를 열지 않고, Core는 Runner를 호출하지 않는다.

**"VM 공간 배정"의 의미**: 로그인 시 Workspace(D1 행 + R2 경로)·Plan·한도만 논리적으로 배정한다. 물리 자원은 작업 실행 시점에만 쓴다.

**Run 상태**: `QUEUED → CLAIMED → RUNNING → VALIDATING → READY | FAILED`. Lease 만료 시 QUEUED 복귀(attempt+1, 최대 2회 시도).
**진행 phase 코드**: `QUEUED, SEARCHING, DRAFTING, VERIFYING, DONE`.

**Plan 프로파일** (`profiles.json`, 가설값 — G3 벤치마크 후 확정)

| 항목 | free | plus | pro |
|---|---|---|---|
| maxChannels | 1 | 3 | 10 |
| minScheduleIntervalMin | 1440 | 360 | 60 |
| dailyRunCap | 3 | 20 | 60 |
| priority | 1 | 2 | 3 |
| cpus | 1 | 2 | 3 |
| memMb | 2048 | 4096 | 6144 |
| timeoutSec | 300 | 600 | 900 |
| maxRepair | 1 | 2 | 3 |
| browser | false | true | true |

**Vista Manifest v1**
```jsonc
{ "schema": 1, "title": "…", "summary": "한두 문장", "entry": "index.html", "poster": "poster.png",
  "aspect": "9:16",            // "9:16" | "free"
  "durationHintMs": 30000,
  "files": [{ "path": "index.html", "sha256": "…", "bytes": 12345 }],
  "generator": { "runId": "…", "modelId": "…" } }
```
제한: 파일 ≤ 12개, 총합 ≤ 3MB, 경로 `^[a-z0-9._-]+(/[a-z0-9._-]+)*$`, 확장자 `html css js json png jpg webp svg woff2`만. 외부 네트워크 요청 금지.

**Player 프로토콜**: 호스트→Vista `{type:"campsite:play"|"campsite:pause"|"campsite:restart"}`, Vista→호스트 `{type:"campsite:ready", durationMs?:number}`. 3초 안에 ready가 없으면 iframe load 이벤트로 대체한다.

**사용자 API**
- `GET /auth/google/start`, `GET /auth/google/callback`, `POST /auth/logout`
- `GET /api/me` → `{user:{id,name,email,avatarUrl}, plan, usage:{channels:{used,max}, runsToday:{used,max}}}`
- `GET /api/channels`, `POST /api/channels {brief}` (첫 Run 자동 생성, `Idempotency-Key` 헤더)
- `POST /api/runs {channelId, prompt}` → 202 `{runId}`
- `GET /api/runs/:id` → `{status, phase, vistaId?, error?}`
- `GET /api/feed?cursor` → `{items:[{vistaId, channelId, channelTitle, title, summary, posterUrl, aspect, createdAt}], nextCursor}`
- `GET /api/vistas/:id` → `{vistaId, title, summary, aspect, playUrl, posterUrl, expiresAt}`

**오류 형식**: `{error:{code}}` — `UNAUTHENTICATED, CHANNEL_LIMIT, RUN_LIMIT, NOT_FOUND, INVALID_REQUEST, RUN_FAILED`.

## 1. 범위

**포함**: 로그인, For Me 피드, 하단 채널 레일, 프로필, 새 채널 패널, 생성 중 상태, Vista Player, 오류·한도 안내.
**제외**: Discovery 동작, 좋아요·댓글·공유·포크, 결제, 모델 연결 화면, 음성 입력, Duo 접힘 레이아웃, 시네마틱 온보딩.
**임의 기능·버튼·패널 추가 금지.** 필요하다고 판단되면 먼저 질문한다.

## 2. 기술 스택

Vite + React + TypeScript · Tailwind · shadcn/ui(Radix) · TanStack Query · React Router · 애니메이션 라이브러리 1개(Motion) · MSW · Vitest · Playwright.
API 응답은 contracts의 Zod 스키마로 검증한다.

## 3. 디자인 원칙

- 배경은 완전한 흰색. 정보량 최소. 놀이터처럼 가볍고 통통 튀는 모션(과하지 않게).
- 설명·검수 문구, 플레이 버튼, 스크롤 위주 화면을 두지 않는다. Vista가 화면 대부분을 차지한다.
- shadcn 컴포넌트를 기본 외형 그대로 쓰지 않는다. `styles/tokens.css`(색·반경·간격·모션 시간)에서 Campsite 스타일로 재정의한다.
- 로고와 브랜드는 아직 없다. 텍스트 워드마크 `campsite`를 임시로 쓴다.
- 뷰포트는 모바일 단일 컬럼(390×844 기준, `100dvh`, safe-area). 데스크톱은 가운데 정렬된 폭 430px 컨테이너.

## 4. 표면 비노출 규칙 (CI에서 강제)

- 사용자에게 보이는 모든 문구는 `src/copy.ts` 한 파일에만 둔다. 컴포넌트에 문자열 하드코딩 금지.
- `copy.test.ts`가 copy.ts의 모든 값에서 금지어를 검사해 하나라도 있으면 실패한다.
  금지어: `Runner, Gateway, R2, VM, Upload, 업로드, Manifest, Lease, Cron, 슬롯, CPU, GB, MB, 토큰, API, Hermes, OpenRouter`
- 오류는 코드→자연어 매핑표(`errorCopy`) 하나로만 표시한다. 코드·스택·HTTP 상태를 사용자에게 보이지 않는다.
- 한도 안내는 수치 표나 사양 대신 한 문장으로 한다. 예: "지금은 채널을 {max}개까지 만들 수 있어요."
- Plan 이름은 프로필 시트 안에서만 표기할 수 있다.

## 5. 컴포넌트 명세 (`components/campsite/`)

1. `AppShell` — `100dvh`, safe-area, 상단 알약, 본문, 하단 레일, 우하단 프로필.
2. `ModePill` — For Me | Discovery 토글(선택 항목 검정 배경, 탄성 전환). Discovery는 빈 화면 한 장과 문구 한 줄만 두고 동작은 구현하지 않는다.
3. `ChannelRail` — 하단 원형 채널 버튼 + 새 채널(+). 채널 버튼은 **지침이 아니라 그 채널의 최신 결과(poster)** 를 원 안에 보여준다. 결과가 없으면 단색 원.
4. `FeedPager` — 가로 이동은 채널 레일, 세로 스와이프는 같은 채널의 이전·이후 Vista. 현재 Vista만 iframe을 mount하고, 인접 항목은 poster만 로드한다.
5. `VistaFrame` — iframe 래퍼(7절).
6. `NewChannelPanel` — 위에서 아래로 열리는 패널. 열리면 앱 화면 전체(상태바 영역 포함)가 아래로 밀려 내려가고 위에 입력 공간이 생긴다. 텍스트 입력 1칸과 보내기만 둔다.
7. `ProfileButton` + `ProfileSheet` — 우하단 원형 아바타. 시트에는 이름, 이메일, 로그아웃만 둔다.
8. `StatusLine` — 생성 상태를 자연어 한 줄로 표시.
9. `EmptyState` — 채널이 없을 때 한 줄 안내.

## 6. 상태별 동작

- **비로그인**: 워드마크와 `Continue with Google` 버튼 하나.
- **채널 0개**: 새 채널 패널을 열린 상태로 시작한다(빈 화면 방지). ← 확인이 필요하면 질문할 것.
- **생성 중**: 채널이 레일에 즉시 나타나고 본문에 StatusLine과 부드러운 모션을 보여준다.
  phase 문구 매핑(copy.ts): QUEUED "준비하고 있어요" · SEARCHING "자료를 찾고 있어요" · DRAFTING "Vista를 만들고 있어요" · VERIFYING "마무리하고 있어요" · DONE "Vista가 도착했어요".
- **도착**: 사용자가 그 채널을 보고 있으면 전환 모션 후 자동 재생.
- **실패**: "만들지 못했어요." + "다시 시도" 버튼 하나(같은 prompt로 `POST /api/runs`).
- **한도(`CHANNEL_LIMIT`, `RUN_LIMIT`)**: 4절 규칙의 한 문장 안내.
- **네트워크 오류**: 토스트 하나. **세션 만료**: 로그인 화면으로.

## 7. Vista Player 명세

- `<iframe sandbox="allow-scripts" referrerpolicy="no-referrer" allow="">` 고정. `allow-same-origin`, `allow-top-navigation`, `allow-forms`, `allow-popups`는 **금지**하고 테스트로 고정한다.
- `src`는 `playUrl`(별도 Vista 도메인의 서명 경로). `expiresAt`이 임박하면 `GET /api/vistas/:id`로 갱신한다.
- 화면에 보이는 Vista만 `campsite:play`를 보내고, 벗어나면 `campsite:pause`, 다시 돌아오면 `campsite:restart`를 보낸다.
- `ready`가 3초 안에 없으면 load 이벤트로 대체한다. 10초 넘게 로드되지 않으면 poster를 유지하고 조용히 재시도한다.
- 9:16 Vista는 contain으로 맞추고 남는 영역은 흰색. `aspect: "free"`는 꽉 채운다.
- 호스트 UI(알약·레일·프로필)는 iframe 위의 **독립 레이어**다. Vista 내용을 읽거나 조작하지 않고 메시지만 주고받는다.

## 8. 데이터 계층

- `lib/api.ts`: `credentials: "include"`, Zod 파싱, 오류를 `{code}`로 정규화.
- Query keys: `me, channels, feed, run(id)`.
- 폴링: 활성 run이 있으면 `GET /api/runs/:id`를 3초마다, 종료되면 feed를 invalidate. 피드는 포커스·재연결 시 refetch, 활성 run 동안 10초마다 refetch.
- Mock: MSW 핸들러는 contracts의 fixture를 재사용한다. `VITE_API_MODE=mock|real`. G1 통과 후 기본값을 `real`로 바꾼다.

## 9. 단계와 완료 기준 (DoD)

**Phase A — 디자인 시스템과 mock 흐름**
`/__dev` 프리뷰 페이지에 모든 컴포넌트·상태를 나열한다.
DoD: 390×844에서 모든 상태가 렌더링, `copy.test.ts` 통과, 기본 접근성(role·label·포커스) 확인.

**Phase B — 로그인·채널 생성·상태 전이 (mock)**
DoD: Playwright 모바일 e2e(mock)에서 로그인 → 채널 생성 → StatusLine 전이 → 도착 → `campsite:play` 전송까지 통과.

**Phase C — 실제 API 연결 (G1·G2)**
DoD: 실제 Core·Runner 대상 e2e 통과, 새로고침 후에도 피드 유지, iframe sandbox 속성 테스트 통과, 실제 모델이 만든 Vista 재생.

**Phase D — 모바일 검수**
iPhone Safari 또는 시뮬레이터에서 `dvh`·safe-area·스와이프 충돌·모션 성능 점검.
DoD: 점검 결과와 수정 목록 보고.

## 10. 하지 말 것

- 화면에 사양, 용량, 기술 용어, 오류 코드를 노출하지 않는다.
- Vista 안쪽 UI를 호스트가 대신 그리지 않는다. 플레이 버튼, 하단 설명·검수 문구를 만들지 않는다.
- contracts, `services/**`를 수정하지 않는다.
- 큰 시각 변경은 의도를 먼저 설명하고 확인받는다.
