# Campsite R5.8 — 세션 2: Runner 컨테이너 (Hermes Agent 기반)

문서 버전: R5.8-S2 · 2026-10-10
소유 폴더: `services/runner/**` 만 수정한다. 그 외는 읽기 전용.

## 역할과 목표

프롬프트를 받아 **실제 HTML 모션그래픽 Vista**를 만들어 내는 Campsite Runner를 Docker 컨테이너로 만든다.
Hermes Agent(NousResearch/hermes-agent, MIT)를 기반으로 다듬되, **Campsite가 `run(job)` 계약을 소유**한다. Hermes는 그 안의 교체 가능한 구현 요소다.

핵심 순서: **① Core 없이 단독 실행으로 품질부터 잡는다 → ② Core에 연결한다.**

## 0. 공통 전제 (읽기 전용)

> 원본은 `packages/contracts`(세션 3 소유). 이 절과 다르면 contracts가 이긴다. 계약 변경은 세션 3에만 요청한다.

**이번 목표 = For Me까지.** Google 로그인 → Workspace·Plan 논리 배정 → 채널 생성(프롬프트) → Runner가 HTML 모션그래픽 Vista 생성 → 웹앱 Vista Player 재생 · For Me 피드.
**제외**: 결제, Discovery 동작, 사용자 모델 연결(G3), 채널 정기 실행(G4), Duo 접힘 레이아웃, 좋아요·댓글·포크.

**구조**: Web(`apps/web`) → Core(`services/core`: Cloudflare Worker + D1 + R2) ← outbound HTTPS만 ← Runner(`services/runner`: VPS의 Docker). Runner는 인바운드 포트를 열지 않고, Core는 Runner를 호출하지 않는다.

**"VM 공간 배정"의 의미**: 로그인 시 Workspace(D1 행 + R2 경로)·Plan·한도만 논리적으로 배정한다. 물리 자원은 작업 실행 시점에만 쓴다.

**Run 상태**: `QUEUED → CLAIMED → RUNNING → VALIDATING → READY | FAILED`. Lease 만료 시 QUEUED 복귀(attempt+1, 최대 2회 시도).
**진행 phase 코드**: `QUEUED, SEARCHING, DRAFTING, VERIFYING, DONE`.

**Plan 프로파일** (`profiles.json`, 가설값 — G3 벤치마크 후 확정)

| 항목 | free | plus | pro |
|---|---|---|---|
| maxChannels | 1 | 3 | 10 |
| minScheduleIntervalMin | 1440 | 360 | 60 |
| dailyRunCap | 3 | 20 | 60 |
| priority | 1 | 2 | 3 |
| cpus | 1 | 2 | 3 |
| memMb | 2048 | 4096 | 6144 |
| timeoutSec | 300 | 600 | 900 |
| maxRepair | 1 | 2 | 3 |
| browser | false | true | true |

**Vista Manifest v1**
```jsonc
{ "schema": 1, "title": "…", "summary": "한두 문장", "entry": "index.html", "poster": "poster.png",
  "aspect": "9:16",            // "9:16" | "free"
  "durationHintMs": 30000,
  "files": [{ "path": "index.html", "sha256": "…", "bytes": 12345 }],
  "generator": { "runId": "…", "modelId": "…" } }
```
제한: 파일 ≤ 12개, 총합 ≤ 3MB, 경로 `^[a-z0-9._-]+(/[a-z0-9._-]+)*$`, 확장자 `html css js json png jpg webp svg woff2`만. 외부 네트워크 요청 금지.

**Player 프로토콜**: 호스트→Vista `{type:"campsite:play"|"campsite:pause"|"campsite:restart"}`, Vista→호스트 `{type:"campsite:ready", durationMs?:number}`. 3초 안에 ready가 없으면 iframe load 이벤트로 대체한다. **shim(`campsite-vista.js`)은 이 세션이 만든다(3.3절).**

**Runner API** (모두 `Authorization: Bearer <노드 토큰>`)
- `POST /runner/register {nodeId, hostCpus, hostMemMb, version}`
- `POST /runner/claim {nodeId, freeMemMb, freeCpus}` → 200 Job | 204. Core는 `reqMemMb ≤ freeMemMb`, `reqCpus ≤ freeCpus`인 QUEUED 중 priority가 높은 것부터 원자적으로 배정한다.
- `POST /runner/runs/:id/heartbeat {phase}` → `{leaseUntil, cancel:boolean}`
- `PUT /runner/runs/:id/files/<path>` (원본 바이트, 헤더 `x-sha256`) → 파일 1개씩 스테이징
- `POST /runner/runs/:id/submit {manifest, usage:{tokensIn,tokensOut,durationMs}}` → 201 `{revisionId}` | 422 `{errors[]}`
- `POST /runner/runs/:id/fail {code, retryable}`

**Job** (claim 응답)
```jsonc
{ "runId": "…", "channelId": "…", "attempt": 1,
  "prompt": "이번 요청", "channelBrief": "채널 지침",
  "recent": [{ "title": "…", "summary": "…" }],      // 같은 채널 최근 3개
  "profile": "free|plus|pro",
  "limits": { "cpus": 1, "memMb": 2048, "timeoutSec": 300, "maxRepair": 1, "browser": false },
  "model": { "provider": "openrouter", "modelId": "…", "apiKey": "…" },   // 단기 전달. 로그·디스크 기록 금지
  "artifactVersion": "1" }
```

**실패 코드**: `MODEL_ERROR, TIMEOUT, VALIDATION_FAILED, TOOL_ERROR, OOM, CANCELED`.

## 1. 선행 조건

- Hermes 저장소: `github.com/NousResearch/hermes-agent` (MIT). 라이선스 고지를 유지한다.
- 개발용 OpenRouter 키(사용 한도 설정). 파일럿 단계에서 Core가 이 키를 claim 응답으로 전달한다.
- Docker가 가능한 개발 환경과 VPS(Docker 설치 가능한 소형 서버).
- 이 세션의 단독 실행 단계(Phase 1)는 Core·Cloudflare 없이 가능하다.

## 2. Phase 0 — Hermes 판정 스파이크 (시간 상한: 1일)

아래를 확인해 `services/runner/docs/hermes-spike.md`에 **한 페이지**로 정리한다.

1. 헤드리스 단일 실행 진입점이 있는가(대화형 CLI·메신저 게이트웨이 없이 프로그램에서 호출 가능한가).
2. OpenRouter를 Provider로 쓸 수 있는가, 모델·키를 환경변수로 주입할 수 있는가.
3. 도구(Tool) 세트를 실행 시점에 끄고 켤 수 있는가(Free는 Browser 도구가 **등록 자체가 안 되어야** 한다).
4. 상태 디렉터리(`~/.hermes` 등)를 작업 컨테이너의 `/work`로 옮길 수 있는가. 작업 간 상태가 새지 않아야 한다.
5. 내장 Cron·Memory는 이번 단계에서 **사용하지 않는다**(스케줄 소유자는 Core 단독).

**판정**: A) 그대로 재사용 · B) 일부 모듈만 재사용(어댑터 뒤에 둠) · C) 폴백. 시간 상한 안에 A·B가 안 되면 **C: Provider 직접 호출 + 단순 도구 루프**로 간다. 판정 때문에 일정을 막지 않는다.

모든 경우에 아래 인터페이스 뒤에 숨긴다.
```
AgentEngine.run(job, ctx) → AsyncIterable<Event>   // Event: phase 변경 | 로그 | 산출물 준비됨
```

## 3. Phase 1 — Core 없이 단독 실행 (G1과 병행)

### 3.1 단독 CLI와 컨테이너
- `docker run campsite-agent --job job.json --out out/` 한 줄로 `out/`에 Vista(`index.html`, `poster.png`, `manifest.json`)가 나와야 한다.
- 샘플 job 3개를 `services/runner/prompts/bench-*.json`에 둔다(예: "오늘의 AI 업계 변화 시각화", "HBM 시장 구도 비교", "이번 주 거시경제 한 장").
- Dockerfile: Python + Chromium(Playwright), **비루트 사용자**, 읽기 전용 루트 파일시스템 + `/work` tmpfs.
- `--stub` 모드: 모델 없이 고정 HTML을 생성한다. 세션 3과 G1 배관 테스트에 쓴다.

### 3.2 모델 키
- job의 `model.apiKey`는 컨테이너 env로만 주입한다. 디스크·로그·산출물에 쓰지 않는다. 로그에서 마스킹한다.

### 3.3 Vista Authoring Kit (`services/runner/kit/`) — **품질의 핵심, 가장 먼저 만든다**
- **시스템 프롬프트**: 산출물 규격(Manifest 제한, 외부 요청 금지, 단일 `index.html` 인라인 권장), 9:16 스테이지(1080×1920 기준 scale-to-fit), 20~45초 모션 구성, 정보 구조(핵심 한 줄 → 근거 시각화 → 변화·비교), 출처 표기 방식.
- **디자인 토큰**: CSS 변수 세트(흰 배경 기반, 강조색, 모션 이징·시간).
- **vendor 라이브러리**: 오프라인으로 번들한 승인 목록. **라이선스를 확인한 것만** 넣는다(후보: D3, anime.js 등). 네트워크로 라이브러리를 받는 코드를 허용하지 않는다.
- **`campsite-vista.js` shim**: 호스트의 play/pause/restart 메시지를 받아 `document.getAnimations()`와 사용자 훅(`Campsite.onPlay/onPause/onRestart`)에 연결하고, 준비되면 `campsite:ready`를 보낸다. 모든 Vista가 이것을 포함한다.
- **참고 Vista 3~5개**: 손으로 다듬은 좋은 예시(few-shot). 이 예시의 품질이 생성 품질의 상한이 된다.

### 3.4 검증기 (`services/runner/validator/`, 네트워크 없는 별도 컨테이너)
1. Manifest 스키마, 파일 수·용량·확장자·경로·sha256 검사.
2. 정적 검사: `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `import()`·외부 URL(`http(s)://`) 참조, `eval` 류 금지(사용 시 실패).
3. Playwright로 로드: 콘솔 오류·미처리 예외 0, `campsite:ready` 수신 또는 load 완료.
4. 움직임 확인: 0초와 2초 시점 스크린샷의 픽셀 차이가 임계 이상이어야 한다(정지 화면 방지).
5. `poster.png` 생성(0.5~1초 시점 캡처).
6. 실패 시 오류 요약을 모델에 되먹여 수리 루프를 돈다(최대 `limits.maxRepair`회). 모두 실패하면 `VALIDATION_FAILED`.
- Chromium의 sandbox 문제로 `--no-sandbox`를 쓰게 되면, 컨테이너 격리(seccomp·비루트·네트워크 차단)에 의존한다는 점을 문서에 명시한다.

### 3.5 Phase 1 DoD
- 표준 프롬프트 3개 모두 `out/`에 검증 통과한 Vista가 나온다.
- Free 설정에서 Browser 도구가 **등록되지 않음**을 테스트로 증명한다.
- 사람이 `out/index.html`을 브라우저로 열어 보았을 때 모션이 있고 한 화면에 읽을 수 있는 정보 구조임을 확인한다(스크린샷 첨부).

## 4. Phase 2 — Runner 데몬과 Core 연결

### 4.1 데몬 (`services/runner/daemon/`, 신뢰 코드)
- 시작 시 `hostCpus`, `hostMemMb`를 감지하고 **자원 예산**을 계산한다: `budgetMem = hostMemMb × 0.75`, `budgetCpu = hostCpus × 1.5`(과할당 허용, 벤치마크 후 조정). 이것이 "VM마다 최적화"다.
- `register` 후 `claim {freeMemMb, freeCpus}`를 폴링한다(작업 중 5초, 유휴 15초, 오류 시 지수 백오프). 수락한 job의 `limits`만큼 free를 차감하고 종료 시 반환한다.
- 알려진 한계: 큰 job이 작은 job 때문에 늦어질 수 있다. 이번 단계에서는 우선순위 정렬로 완화하고 벤치마크에서 관찰만 한다.
- heartbeat는 30초마다. 응답의 `cancel:true`를 받으면 컨테이너를 종료하고 `CANCELED`로 처리한다.

### 4.2 작업 컨테이너 실행 (`docker run` 플래그)
`--cpus <limits.cpus> --memory <limits.memMb>m --memory-swap <동일> --pids-limit 256 --read-only --tmpfs /work --cap-drop ALL --security-opt no-new-privileges --network campsite-jobs`, 타임아웃은 `limits.timeoutSec`(데몬이 강제 종료).
- 컨테이너는 **Core와 직접 통신하지 않는다.** 결과 파일만 `out/`에 쓰고, 검증과 제출은 데몬이 한다.
- `campsite-jobs` 네트워크의 사설 대역·메타데이터 주소 차단 규칙은 세션 3의 `ops/` 런북이 정한다. 이 세션은 네트워크 이름과 필요한 외부 도달 대상(모델 API, 검색)을 문서화한다.
- 실행 순서: 에이전트 컨테이너 → `out/` → **검증기 컨테이너(`--network none`)** → 데몬이 파일별 `PUT` → `submit`.

### 4.3 Plan별 성능 차이를 만드는 수단 (표만이 아니라 강제한다)
cgroup 상한(cpus·memory), 타임아웃, 수리 횟수, Browser 도구 등록 여부, 큐 우선순위(Core). 이 다섯 가지가 Free와 Pro의 실제 차이다.

### 4.4 로그와 벤치마크
- 작업마다 JSON 한 줄: `runId, profile, durationMs, peakMemMb, repairCount, tokensIn, tokensOut, validatorResult, failCode`.
- `scripts/bench.sh`: 표준 프롬프트 3개를 Free·Plus·Pro 설정으로 각각 실행해 표로 요약한다.

### 4.5 Phase 2 DoD
- Core의 stub 구현(또는 실제 Core)에 register → claim → heartbeat → 파일 PUT → submit이 통과한다.
- 컨테이너에서 `169.254.169.254`와 사설 대역에 접근이 차단됨을 확인한다(세션 3 런북 적용 후).
- 같은 프롬프트의 Free·Pro 실행 결과가 로그에서 **측정 가능하게 다르다**(시간·수리 횟수·Browser 사용 여부).
- 데몬을 재시작해도 이미 제출된 Vista에 영향이 없고, 중단된 작업은 Lease 만료로 재큐잉된다.

## 5. 배포 산출물

- `services/runner/deploy/campsite-runner.service`(systemd 유닛 템플릿)와 환경변수 목록(`CORE_URL`, `NODE_TOKEN`, `NODE_ID`, `POOL`).
- 이미지 빌드·실행 방법을 `services/runner/README.md`에 적는다. VM 방화벽·사용자·업데이트 설정은 세션 3의 `ops/`가 담당한다.

## 6. 하지 말 것

- Hermes의 Cron·Memory·메신저 게이트웨이를 이번 범위에 끌어오지 않는다.
- 작업 컨테이너에 노드 토큰이나 호스트 디렉터리를 마운트하지 않는다. 컨테이너가 Core를 직접 호출하게 하지 않는다.
- 프롬프트만으로 Free의 Browser를 "쓰지 말라"고 지시하는 것으로 끝내지 않는다(도구 등록 자체를 막는다).
- contracts와 `apps/web`, `services/core`를 수정하지 않는다. 계약 변경은 세션 3에 요청한다.

## 7. 보고 형식

Phase가 끝날 때마다 보고한다: 구현/미구현, DoD 체크 결과, 벤치마크 표, 세션 3에 요청할 계약 변경, 발견한 위험(특히 Vista 품질과 Hermes 이식 이슈).
